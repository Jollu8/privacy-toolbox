# Privacy Toolbox: план реализации

Этапы 1–3 реализованы: каталог содержит 20 инструментов. Этап 4 описывает будущие расширения. Детальное поведение — в [PRODUCT.md](PRODUCT.md); будущий протокол — в [WORKER_API.md](WORKER_API.md).

## Текущее состояние

Работают все 20 основных страниц и три старых совместимых адреса. Есть общий Worker API v1, lazy Pyodide/Pillow, локальный QR, адаптивный каталог и workflow Pages. Наличие workflow не означает, что сайт уже опубликован.

Hash читает чанки по 4 MiB; браузерная проверка включает 68 MiB файл. Другие файлы ограничены 64 MiB, текст — 8 MiB UTF-8, изображения — 20 MP. Diff: 200 000 символов и 5000 строк на ввод. C++, offline-режим и история отсутствуют.

## Этап 1 — основа и простые инструменты

- [x] File Hash, Tracking URL Cleaner, JSON Formatter, Base64.
- [x] Общий Worker, локальная обработка, копирование и ошибки.
- [x] Password Generator с `secrets`, настройками групп и безопасной обработкой ошибок RNG.
- [x] UUID v4 Generator, пакетная генерация, Copy one/all, TXT.
- [x] Версионированный единый Worker API: structured errors, единый result и metadata; совместимая миграция шести инструментов.
- [x] Канонические страницы `file-hash/`, `json-formatter/` и сохранение старых адресов.
- [x] Общие breadcrumbs, Clear, About this tool, How it works и FAQ.
- [x] Отступ и независимая сортировка JSON; экспорт Base64 в TXT; opt-in удаления ref/referrer.

Критерий завершения: новые генераторы работают в реальном Pyodide, не используют слабый RNG, не сохраняют секреты; прежние шесть инструментов проходят regression checks. Каждая доступная карточка ведёт на работающую страницу.

## Этап 2 — файлы и изображения

- [x] Удаление метаданных пересозданием пикселей и compressor JPEG/PNG/WebP.
- [x] Inspect metadata до удаления: камера, дата, GPS, ПО.
- [x] Целевой адрес `remove-image-metadata/` с сохранением старого.
- [x] Keep original, согласованное качество JPEG/WebP и фактическая статистика сжатия.
- [x] Image Resizer: пропорции, размеры и presets.
- [x] Image Converter: PNG/JPEG/WebP/BMP.
- [x] Chunked file hashing с backpressure, прогрессом, отменой и ограниченной памятью.

Критерий завершения: скачанные файлы открываются, ориентация и прозрачность соответствуют настройкам; метаданные отсутствуют в проверяемых выходных контейнерах. Hash совпадает с эталоном для файлов больше текущего лимита, без линейного роста памяти по размеру файла. Лимиты обновляются только после измерений.

## Этап 3 — полный каталог из 20 инструментов

- [x] Отдельная страница JSON Validator на общем парсере.
- [x] Secure Random Token Generator.
- [x] CSV ↔ JSON.
- [x] Text Cleaner.
- [x] Duplicate Line Remover.
- [x] Text Diff.
- [x] Timestamp Converter.
- [x] URL Encoder / Decoder.
- [x] JWT Decoder с постоянным предупреждением о непроверенной подписи.
- [x] QR Generator с локальной библиотекой и PNG/SVG.
- [x] Компактный каталог из шести категорий, поиск и мобильная адаптация.

Этот этап включает Token, URL Encoder, QR и отдельный Validator, чтобы ни один из 20 инструментов не потерялся между этапами исходного предложения.

Критерий завершения: все 20 целевых страниц имеют работающий ввод/результат, содержательное описание, ограничения и тесты основной логики. QR проверяется обратным декодированием; преобразования имеют round-trip tests там, где формат допускает обратимость. Для Text Diff отдельно проверяется отзывчивость и отмена.

## Этап 4 — установка и удобство

- [ ] Self-hosted runtime и библиотеки с фиксацией версий.
- [ ] Service Worker, управляемое кеширование, PWA/installability.
- [ ] Offline-проверки после установки: различать закешированные и ещё недоступные инструменты.
- [ ] Светлая/тёмная тема и переводы интерфейса.

Критерий завершения: offline-обещание подтверждается запуском без сети, обновление кешей не смешивает несовместимые версии, отключение истории действительно предотвращает сохранение ввода.

## Порядок работы над одним инструментом

1. Выбрать инструмент и уточнить его лимиты/краевые случаи из PRODUCT.md.
2. Реализовать логику и проверяемый контракт; добавить страницу общего вида.
3. Проверить нормальный результат, ошибочный и пустой ввод, границы, отмену и повторный запуск.
4. Проверить реальный браузер, мобильную ширину, клавиатуру, подпапку GitHub Pages и сетевые запросы.
5. Только затем добавить работающую карточку и обновить статус в документации.

Выбор C++/WASM делается для отдельной измеренной задачи. Он не блокирует выпуск Python-инструментов. Публичная публикация и выбор лицензии — отдельные задачи выпуска; эта документация сама по себе их не выполняет.
