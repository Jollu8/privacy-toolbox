# Privacy Toolbox: спецификация продукта

Реализован единый набор из **20 локальных браузерных инструментов**. Документ фиксирует общую структуру, поведение и ограничения. Выполненные этапы и будущие расширения описаны в [ROADMAP.md](ROADMAP.md). Необязательные расширения помечены отдельно.

## Принцип продукта

> Все пользовательские данные обрабатываются локально в браузере. Файлы и ввод не загружаются на сервер. Регистрация не требуется.

Статические страницы размещаются на GitHub Pages. Загрузка runtime и библиотек может обращаться к CDN; блок privacy сообщает об этом прямо. Нельзя обещать отсутствие сетевых подключений или offline-работу до реализации и проверки соответствующих функций.

## Единый интерфейс

Каждая страница включает:

1. Навигацию `Home / Category / Tool`, заголовок и короткое объяснение задачи.
2. Ввод слева и результат справа; на телефоне результат расположен ниже ввода. Файлы можно выбрать кнопкой или перетащить.
3. Подписанные настройки, основную кнопку действия и состояния: ожидание, загрузка движка, обработка, результат, ошибка, отмена.
4. Копирование текстового результата и скачивание поддерживаемого файла. При изменении ввода старый результат скрывается. Никаких автоматических скачиваний.
5. Заметную надпись `Processed locally in your browser` и объяснение загрузки runtime.
6. `About this tool`, `How it works` и короткий FAQ с ограничениями именно этого инструмента.

Форма работает с клавиатуры, ошибки читаются через live region, прогресс не передаётся одним цветом. Пользовательские строки выводятся как текст, а не HTML. Копирование имеет запасной вариант с выделением текста. Кнопка Clear очищает ввод и результат в текущей форме, не меняя другие страницы.

Главная начинается с короткого заголовка, поиска и категорий Files / Privacy / Data / Text / Developer / Utility. Большой рекламный блок и дублирующий список популярных инструментов убраны. На desktop инструменты расположены в компактной сетке; на телефоне — в один столбец, с горизонтально прокручиваемыми категориями. Краткое пояснение локальной обработки находится под каталогом. Поиск выполняется на JavaScript без загрузки Python и учитывает названия, описания и категории. Запрос `json` находит Formatter, Validator и CSV ↔ JSON. На пустой результат выводится понятное сообщение.

## Files

### 1. File Hash Calculator

- Выбор файла; имя и размер; алгоритм по умолчанию SHA-256. Дополнительно SHA-384, SHA-512, SHA-1 и MD5.
- Результат: название алгоритма, hex digest, Copy.
- Для SHA-1/MD5: `Legacy algorithm — not recommended for security purposes.`
- Python: `hashlib`. Целевой режим больших файлов: чтение порциями примерно по 4 MiB, один incremental hash в Worker, подтверждение обработки перед отправкой следующего чанка и прогресс по байтам. Не собирать весь файл в памяти.
- Отмена или новый расчёт удаляет прежнее состояние хеша. Пустой файл допустим.
- Потоковое хеширование проверено на файле 68 MiB в браузере. Отдельного ограничения размера для hash нет; пример ISO на 5.4 GB не заменяет измерения на конкретном устройстве. Для остальных файлов действует лимит 64 MiB.

### 2. Image Metadata Remover

- После выбора отдельный этап Inspect metadata: камера, дата съёмки, GPS, ПО, размеры. При отсутствии полей выводить `Not found`.
- GPS показывать локально, без карты, геокодирования или внешних запросов. Отображать только корректно разобранные координаты; отсутствие понятного GPS-поля не доказывает отсутствие иных данных о месте.
- Затем Remove metadata: применить EXIF-ориентацию, пересоздать изображение из пикселей, сохранить без исходных EXIF, GPS, текстовых полей и ICC-профиля.
- Результат: удалённые контейнеры, исходный и конечный размер, превью, Download clean image.
- Объяснить JPEG-потери, возможные изменения цветов и сохранение видимого содержимого фотографии. Python: Pillow.

### 3. Image Compressor

- JPEG, PNG, WebP; выбор Keep original или конкретного формата.
- Качество для JPEG/WebP: 30–100, значение по умолчанию 75. Для PNG — оптимизация без ползунка качества.
- Before, After и фактическая экономия после обработки. Если файл вырос, сообщать об этом прямо.
- Не показывать выдуманный Estimated output: предварительная оценка требует отдельного реального кодирования, должна иметь пометку estimate и отменяться при изменении настроек.
- Python: Pillow. Прозрачность при JPEG заполняется выбранным/явно указанным белым фоном.

### 4. Image Resizer

- Показать исходные размеры после применения ориентации. Поля Width и Height, Keep aspect ratio включён по умолчанию.
- При связанном соотношении изменение одного размера пересчитывает другой; округление до ближайшего целого, минимум 1 px.
- Presets 25%, 50%, 75%; 1920px и 1080px означают максимальную длинную сторону, без увеличения исходника.
- Положительные целые размеры, лимит пикселей проверяется и для результата. Без сохранения пропорций допускается явно выбранное растяжение.
- Pillow выполняет resize с качественной ресэмплизацией; результат содержит размеры, размер файла и Download.

### 5. Image Converter

- Вход и выход: PNG, JPEG, WebP, BMP. Дополнительные форматы не рекламировать без проверки поддержки в браузерной сборке.
- Выбор целевого формата; Quality для JPEG/WebP, без него для PNG/BMP.
- Показать исходный и новый формат, размеры и размер файла; корректные MIME и расширение.
- Политика анимации, метаданных, ориентации и прозрачности совпадает с другими image tools. BMP может значительно увеличить размер.

## Privacy

### 6. Tracking URL Cleaner

- Полный HTTP/HTTPS URL → очищенная строка и список удалённых ключей, Clean и Copy.
- Базовые ключи: `utm_source`, `utm_medium`, `utm_campaign`, `utm_content`, `utm_term`, `fbclid`, `gclid`, `dclid`, `msclkid`, `mc_cid`, `mc_eid`; сохранить уже поддерживаемые дополнительные известные ключи.
- `ref` и `referrer` удаляются только при отдельном opt-in: они могут быть функциональными.
- Сохранять порядок, дубликаты, пустые значения и кодирование остальных параметров, а также fragment. Ссылку не открывать.
- Опцию «удалить неизвестные tracking-параметры» не включать без определённого проверяемого правила: неизвестный параметр нельзя надёжно признать tracking-параметром по имени.

### 7. Password Generator

- Length: по умолчанию 20; uppercase, lowercase, numbers, symbols включены. Avoid similar characters — выключен.
- Python `secrets`; запрещены `random`, время и другие предсказуемые источники. Проверить доступность криптографического RNG в целевой Pyodide-сборке; при ошибке генерация завершается без слабого fallback.
- Хотя бы одна группа должна быть выбрана; длина достаточна для включения каждой выбранной группы. Диапазон: 4–256.
- Генерировать равномерно из объединённого алфавита с повтором до выполнения требований групп. Не добавлять предсказуемые символы в фиксированные позиции.
- Generate / Generate again / Copy. Не сохранять пароль в истории, URL, логах или storage.
- Strength допускается как пояснённая оценка, а не гарантия. Для ограниченного группами распределения не выдавать `length × log2(alphabet)` за точную энтропию.
- Memorable passphrase — последующее расширение с проверенным достаточно большим словарём; не генерировать из нескольких демонстрационных слов.

### 8. UUID Generator

- Только UUID v4; Amount, по умолчанию 5, допустимо 1–1000.
- Python `uuid.uuid4()`, проверка version/variant и формата.
- Copy one для строки, Copy all и Download TXT. Не обещать математически невозможное отсутствие коллизий.

### 9. Random Token Generator

- Типы Hex, URL-safe, Base64; число случайных байтов по умолчанию 32, диапазон 1–1024.
- Python `secrets.token_bytes`, `token_hex`, `token_urlsafe`; Base64 кодирует криптографические случайные байты.
- Показать токен, Copy и энтропию исходных байтов (`8 × bytes` bits). Число байтов не равно числу символов кодированного результата.
- Та же политика отсутствия хранения и слабого fallback, что у Password Generator.

## Data

### 10. JSON Formatter

- Input / Output, Format, Minify, Copy, Clear; отступ 2 или 4 пробела и Sort keys.
- Python `json`. Ошибка содержит строку, столбец и понятное сообщение.
- Сохраняется текущая строгая политика: повторные ключи и не-JSON константы отвергаются. Ограничения дробной точности поясняются.

### 11. JSON Validator

- Самостоятельная страница с тем же парсером, что у Formatter.
- Valid JSON либо Invalid JSON с line/column. Все верхнеуровневые JSON-значения допустимы, включая `null`, строки и числа.
- Проверяется синтаксис и принятая политика ключей, а не соответствие JSON Schema. Подсветка ошибки — улучшение интерфейса после основной проверки.

### 12. Base64 Tool

- Четыре режима: Text → Base64, Base64 → Text, File → Base64, Base64 → File.
- UTF-8 для текста, строгая проверка стандартного Base64 с допустимыми пробельными разделителями.
- Copy, Save TXT для кодированного текста; Download для восстановленных байтов. Пустые файлы и текст допустимы.
- При не-UTF-8 байтах предлагать file mode. Имя и MIME исходного файла из Base64 не восстанавливаются автоматически. Base64 не шифрует данные.

### 13. CSV ↔ JSON

- Режимы CSV → JSON и JSON → CSV, Convert, Copy, Download с `.json` или `.csv`.
- Python `csv` и общий строгий JSON parser. CSV имеет строку заголовков; значения остаются строками, включая ведущие нули.
- Поддержать quoted commas, кавычки и переносы строк внутри полей; не делить CSV простым `split(',')`.
- JSON → CSV принимает массив объектов с плоскими скалярными значениями; вложенные структуры отклонять с пояснением. Колонки — объединение ключей в порядке первого появления; отсутствующее/null значение — пустое поле, с объяснением потери различия.
- Дублирующиеся/пустые CSV-заголовки и несовпадающее число полей — ошибки. Пустой JSON-массив даёт пустой CSV.
- Экспорт может содержать значения, интерпретируемые таблицами как формулы. Отдельная опция безопасного spreadsheet-экспорта меняет такие значения явно, без скрытого изменения исходных данных.

## Text

### 14. Text Cleaner

- Remove extra spaces, Remove empty lines, Trim lines включены по умолчанию.
- Convert tabs to spaces, Normalize line endings, Remove non-printable characters выключены.
- Фиксированный порядок: нормализация окончаний → преобразование табуляций (4 пробела) → удаление непечатных символов → схлопывание повторных обычных пробелов внутри строки → trim → удаление пустых строк.
- Не склеивать строки при удалении непечатных символов; сохранять разделители строк и табуляции, если их отдельная опция выключена. При выключенной нормализации сохранять исходные CRLF/LF/CR.
- Before/After показывают Unicode code points, не байты и не визуальные графемы.

### 15. Duplicate Line Remover

- Keep original order включён; Ignore case и Trim spaces выключены.
- По умолчанию сохранять первую строку каждого значения. Ignore case использует `casefold`, но не меняет регистр сохранённой строки. Trim spaces меняет строку перед сравнением и выводом.
- Если порядок не сохраняется — сортировать по ключу сравнения. Строки разбираются через стандартные окончания строк; завершающий перенос не добавляет фиктивную строку.
- Статистика: Input lines, Unique lines, Duplicates removed. Пустые строки обрабатываются как значения; пустой ввод имеет 0 строк.

### 16. Text Diff

- Original text / Modified text, Compare, текстовый unified diff с `-` и `+`, Copy и Download TXT.
- Python `difflib`; пользовательский текст не вставляется в HTML даже при цветной подсветке.
- Added и Removed включают строки replace-блоков; Changed отдельно показывает `min(old_count, new_count)` для этих блоков и не складывается с ними как независимый итог.
- При одинаковом вводе — No differences. Отличие последнего перевода строки отображается явно. Ограничить размер и число строк, поддержать отмену, поскольку сложность сравнения может быть высокой.

## Developer

### 17. Timestamp Converter

- Режим Unix → date с явным выбором seconds/milliseconds; Date → Unix принимает ISO 8601 с `Z` или числовым смещением.
- Дату без timezone трактовать как UTC только с видимой подписью. Не угадывать единицу по длине числа и не использовать неподписанную локальную зону.
- Вывод: UTC, browser local time с названием/смещением зоны, ISO 8601, Unix seconds и milliseconds.
- Python выполняет точные преобразования; JavaScript может форматировать browser local time через браузерные средства. Отрицательные timestamps допустимы в документированном диапазоне. Проверить epoch, отрицательные значения, миллисекунды и смещения.
- Демонстрационные числовые значения рассчитывать тестами, не копировать непроверенные пары из макетов.

### 18. URL Encoder / Decoder

- Encode / Decode; основной режим — отдельный query parameter, где пробел кодируется `%20`, а `+` остаётся буквальным плюсом при decode.
- Python `urllib.parse.quote` / `unquote`; UTF-8 и проверка некорректных percent escape и байтовых последовательностей.
- Full URL mode сохраняет разделители адреса; явно пояснить различие с кодированием значения. При необходимости `application/x-www-form-urlencoded` (`+` как пробел) — отдельный подписанный режим.

### 19. JWT Decoder

- Постоянная надпись: `This tool decodes JWT contents. It does NOT verify the signature.`
- Принимать compact JWT с тремя сегментами, декодировать base64url и строгий JSON в header/payload. Зашифрованные пятисегментные JWE не поддерживать.
- Отдельные Header / Payload и Copy; поля `iat`, `exp`, `nbf` дополнительно отображать как даты UTC при корректном числовом значении. `iss` и `aud` показывать как текст/JSON.
- Все claims недоверенные. Не делать сетевых запросов к `iss`, `jku`, `x5u`, не загружать ключи и не называть токен verified или authenticated. Истечение срока можно показать только как значение из непроверенного payload.

## Utility

### 20. QR Generator

- Text or URL, Size (по умолчанию 512 px), Error correction L/M/Q/H (по умолчанию M).
- Локальная JS-библиотека допустима и позволяет не загружать Pyodide для этого инструмента. Используется локальный snapshot Nayuki с MIT-лицензией и фиксацией SHA-256; внешние скрипты для QR не загружаются.
- Превью, Download PNG и Download SVG; QR создаётся без запроса к внешнему генератору.
- Quiet zone минимум четыре модуля, целый масштаб модулей; при необходимости центрировать QR на холсте выбранного размера. Слишком маленький размер или превышение вместимости — понятная ошибка.
- SVG строится из геометрии QR без вставки пользовательского текста как разметки. Тестировать декодированием готового QR, включая Unicode.

## Архитектура развития

Базовая платформа — HTML/CSS/vanilla JS → Web Worker → Pyodide/Python. Pillow загружается по требованию image tools. Реализованный единый протокол описан в [WORKER_API.md](WORKER_API.md).

C++ допустим как будущий модуль, компилируемый в WebAssembly, если измерения покажут пользу для конкретной операции. Он должен работать через тот же интерфейс Worker, загружаться по требованию и сохранять модель локальной обработки. Сейчас C++-модулей и их build pipeline нет; миграция всей Python-логики не является частью этого плана.

Сайт не сохраняет ввод в истории по умолчанию. Будущая история требует opt-in; пароли, токены и JWT исключаются из неё. Offline/PWA, темы и переводы идут после завершения и проверки инструментария. Статус open-source должен подкрепляться выбранной лицензией; сейчас файл LICENSE отсутствует.
